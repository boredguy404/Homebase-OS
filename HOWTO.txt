HOMEBASE — THE ONE LOCAL LAUNCH GUIDE
=====================================

CHROMEBOOK / LINUX — COPY AND PASTE THIS BLOCK:

cd "$HOME/homebase" && ./homebase-maintenance.sh open

That starts Homebase, waits until it is ready, and opens the current local URL.

If Homebase is not installed yet, use the installer command at the very top of
README.md once. After installation, always use the command above.

EMULATORJS:

The first Chromebook/Linux install automatically downloads and unpacks the
local EmulatorJS runtime (about 290 MB). Do not put it in roms/ yourself.
If Pocket Archive says the runtime is missing, run the README installer line
again; it only downloads EmulatorJS when emulatorjs/data/loader.js is absent.

Recovery:

  cd "$HOME/homebase" && ./homebase-maintenance.sh restart
  cd "$HOME/homebase" && ./homebase-maintenance.sh status
  cd "$HOME/homebase" && ./homebase-maintenance.sh logs

WINDOWS:

Right-click install-windows.ps1, choose Run with PowerShell, then use the
Homebase shortcut it creates. README.md covers the first installation.

Your ROMs, BIOS files, saves, music, and My Library content stay local and are
excluded from the public Git repository.

RELAY — OPTIONAL AI APP + CORE EDITING
======================================

Open Relay inside NovaShell and use AI Connection. Choose OpenAI or OpenRouter.
OpenRouter starts on openrouter/free for low-volume free-model experiments; it
still requires your own OpenRouter key and can be rate-limited. The provider
profile is saved only as local/relay-provider.json (permissions 600), ignored
by Git, and never sent to a hosted NovaShell service.

With a configured provider, Relay can:
  * Generate Web Component apps in user-apps/experiments/.
  * Delete those generated apps from Relay or by deleting that folder.
  * Draft a reviewed replacement for a small, listed core file.

Brain Files is read-only and lets you inspect the locally imported Brain archive.
Core edits are intentionally not automatic. Relay shows the full draft first;
you must review it and type APPLY CORE EDIT to save. Every successful core
write creates a timestamped copy in local/workspace-backups/.

IF A CORE EDIT BREAKS SOMETHING:

1. Restart first:  cd "$HOME/homebase" && ./homebase-maintenance.sh restart
2. Restore the newest matching file from local/workspace-backups/ (the folder
   name tells you which core file it belonged to), then restart again.
3. If you want a clean public version, run the README installer command again.
   It refreshes tracked project files but leaves ignored personal folders such
   as roms/, saves/, covers/, imports/, My Library, and local/ alone.

Treat an API key like a password: never paste it into a GitHub issue, README,
or a generated app. The public repository has no key and no credentials.
